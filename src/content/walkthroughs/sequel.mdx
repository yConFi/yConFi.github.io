### Conectarse a MariaDB

Mi primer intento fue `mysql -u root`, sin indicar el servidor:

```text
ERROR 2002 (HY000): Can't connect to local server through socket '/run/mysqld/mysqld.sock' (2)
```

Sin `-h`, el cliente se conecta a `localhost`, y en ese caso usa un socket Unix de la propia Pwnbox, donde no
hay ningún servidor. Lo repetí con `-p` (para que pidiera contraseña) y con otro usuario, y el error era el
mismo, porque el problema no era el usuario sino el servidor. Añadiendo `-h` con la IP de la máquina cambió el
error (`mysql -h 10.129.96.217 -u root`):

```text
ERROR 2026 (HY000): TLS/SSL error: SSL is required, but the server does not support it
```

Esta vez sí llega al servidor, pero el cliente se niega a seguir sin cifrado. Según las notas de MariaDB
11.4, desde esa versión los clientes exigen SSL por defecto, y el de Pwnbox es la 11.8.6; el servidor, en
cambio, es una 10.3.27 que no lo admite. Como dice la ayuda, el SSL se desactiva con `--skip-ssl`:

<Cmd
  c="mysql -u root -h 10.129.96.217 --skip-ssl"
  notas={{
    "root": "Usuario de MariaDB con el que se inicia sesión: el administrador.",
    "10.129.96.217": "IP de la máquina objetivo.",
  }}
/>

```text
Welcome to the MariaDB monitor.  Commands end with ; or \g.
Your MariaDB connection id is 65
Server version: 10.3.27-MariaDB-0+deb10u1 Debian 10
...
MariaDB [(none)]>
```

Entra como **root**, el administrador de la base de datos, **sin pedir contraseña**. El prompt `MariaDB [(none)]>` indica que
todavía no hay ninguna base de datos seleccionada.

<Pista titulo="Tarea 4 · ¿Qué usuario permite iniciar sesión en esta instancia de MariaDB sin dar contraseña?">
  **root**.
</Pista>

El propio mensaje de bienvenida lo recuerda: cada orden termina con `;` (o con `\g`).

<Pista titulo="Tarea 6 · En SQL, ¿con qué símbolo hay que terminar cada consulta?">
  **;** (punto y coma).
</Pista>

### Buscar la flag

Listo las bases de datos del servidor:

```text
MariaDB [(none)]> show databases;
+--------------------+
| Database           |
+--------------------+
| htb                |
| information_schema |
| mysql              |
| performance_schema |
+--------------------+
4 rows in set (0.010 sec)
```

Tres de ellas son del propio servidor y salen en cualquier instalación:

- `information_schema`: información sobre las demás bases de datos, sus tablas y sus columnas.
- `mysql`: tablas de sistema con los usuarios, sus permisos y la configuración global.
- `performance_schema`: datos internos para medir el rendimiento del servidor.

La que no es estándar es `htb`.

<Pista titulo="Tarea 7 · Hay tres bases de datos que son comunes a todas las instancias de MySQL. ¿Cómo se llama la cuarta, la que es propia de este equipo?">
  **htb**.
</Pista>

La selecciono con `use` y listo sus tablas:

```text
MariaDB [(none)]> use htb;
Database changed
MariaDB [htb]> show tables;
+---------------+
| Tables_in_htb |
+---------------+
| config        |
| users         |
+---------------+
2 rows in set (0.009 sec)
```

El prompt pasa a ser `MariaDB [htb]>`: `use` deja `htb` como base de datos por defecto hasta que se cierre la
sesión o se use otra.

<Pista titulo="Tarea 8 · ¿Qué orden de MySQL sirve para seleccionar la base de datos con la que trabajar?">
  **use**.
</Pista>

Hay dos tablas, `config` y `users`. Saco todo el contenido de `config` con `select`: el `*` significa todas
las columnas.

```text
MariaDB [htb]> select * from config;
+----+-----------------------+----------------------------------+
| id | name                  | value                            |
+----+-----------------------+----------------------------------+
|  1 | timeout               | 60s                              |
|  2 | security              | default                          |
|  3 | auto_logon            | false                            |
|  4 | max_size              | 2M                               |
|  5 | flag                  | [flag oculta]                    |
|  6 | enable_uploads        | false                            |
|  7 | authentication_method | radius                           |
+----+-----------------------+----------------------------------+
7 rows in set (0.008 sec)
```

<Pista titulo="Tarea 5 · En SQL, ¿qué símbolo se usa en la consulta para indicar que queremos mostrar todo lo que hay en una tabla?">
  **\*** (asterisco).
</Pista>

La fila 5 tiene `flag` en la columna `name`, y su `value` es la flag.

<Pista titulo="Tarea 10 · ¿Qué tabla tiene una fila con un valor llamado flag en una de sus columnas?">
  **config**.
</Pista>

Para ver qué columnas tiene una tabla sin sacar sus datos está `describe` (un atajo de `SHOW COLUMNS FROM`).
En mi sesión lo usé mal: escribí `describe htb;`, primero sin ninguna base de datos seleccionada (*No database
selected*) y luego dentro de `htb` (*Table 'htb.htb' doesn't exist*). Las dos veces falló porque `htb` es una
base de datos, no una tabla; lo correcto habría sido, por ejemplo, `describe config;`.

<Pista titulo="Tarea 9 · ¿Qué orden de MySQL muestra las columnas de una tabla?">
  **describe**.
</Pista>

La flag no se publica: la tienes que conseguir tú.

<Pista titulo="Flag · Envía la flag que está en la base de datos">
  Está en la tabla `config` de la base de datos `htb`: es el `value` de la fila cuyo `name` es `flag`.
</Pista>

## Escalada de privilegios

No hace falta: la flag se lee directamente de la base de datos de MariaDB, sin llegar a tener una shell en la
máquina.

## Lecciones aprendidas

- **Qué fallé:** intenté conectarme varias veces sin `-h`, así que el cliente buscaba un servidor en la propia
  Pwnbox (llegué a probar como usuario `mysql_native_password`, que es el nombre del método de autenticación).
  Ante el error de SSL instalé con `apt` todos los paquetes `mysql*`, que no hacían falta: bastaba con
  `--skip-ssl`. Dentro de MariaDB escribí `cd ..` como si estuviera en el terminal y usé `describe` sobre una
  base de datos en vez de sobre una tabla.
- **Lo que enseña la máquina:** un servidor de bases de datos expuesto en la red con el usuario root sin
  contraseña deja leer y modificar todos sus datos a cualquiera que llegue a su puerto.
- **Qué haré la próxima vez:** indicar siempre el servidor con `-h` al usar un cliente de red y leer bien el
  mensaje de error antes de instalar nada: en este caso, la ayuda del cliente ya decía cómo desactivar el SSL.
